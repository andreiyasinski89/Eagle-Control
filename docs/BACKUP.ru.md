# Резервные копии базы MLM CRM

Каждую ночь (в 02:30 по UTC, это утро по Варшаве/Киеву) GitHub Actions делает полную копию базы Neon, **доказывает, что её можно восстановить**, шифрует и кладёт в хранилище другого провайдера (Backblaze B2). Если что-то идёт не так, GitHub присылает вам письмо «Run failed».

Встроенное восстановление Neon хранит историю часами: это не бэкап. Эта копия лежит в другом месте и хранится месяцами.

## Как это устроено

1. `pg_dump` читает базу пользователем `backup_reader`, у которого есть **только чтение**.
2. Копия тут же восстанавливается в одноразовую пустую базу на сервере GitHub: проверяются число таблиц и количество строк в главных таблицах (пользователи, кабинеты, контакты, участники). Если что-то не совпало, копия считается плохой и запуск краснеет.
3. Копия **шифруется открытым ключом** (`age`). Открытым ключом можно только запереть; открыть можно только закрытым, который есть **только у вас**. У GitHub и у хранилища читать копии нечем.
4. Зашифрованный файл уходит в хранилище: `daily/ГГГГ-ММ-ДД.dump.age`, по воскресеньям ещё и `weekly/`, первого числа ещё и `monthly/`. Старые удаляются правилами хранилища: **7 ежедневных, 4 еженедельных, 3 ежемесячных**.
5. Размер файла в хранилище сверяется с отправленным.

В журнале запуска (он публичный, репозиторий открыт) нет ни адресов, ни паролей, ни данных: только названия шагов, размеры и «ОК/ошибка».

## Настройка (один раз, около 40 минут)

### 1. Ключи шифрования (на вашем компьютере)
Скажите мне, что готовы, я запущу команду, которая создаст пару ключей. **Закрытый ключ** сохранится в файл на рабочем столе `MLM-CRM-backup-PRIVATE-KEY.txt` (в чат он не выводится). Откройте файл, скопируйте строку `AGE-SECRET-KEY-1...` в **менеджер паролей** (подойдёт Bitwarden: бесплатно, есть приложение для телефона и ноутбука; Google Authenticator для этого не подходит, он хранит только одноразовые коды), перепишите ключ **на бумагу** и храните дома отдельно, затем удалите файл с рабочего стола. Без закрытого ключа копии не открыть никому, в том числе мне.
**Открытый ключ** (начинается с `age1`) скрипт напечатает в конце: он нужен для шага 5.

### 2. Хранилище: Backblaze B2 (первые 10 ГБ бесплатно)
1. Зарегистрируйтесь на https://www.backblaze.com/sign-up/cloud-storage (B2 Cloud Storage).
2. **Buckets → Create a Bucket**: имя любое уникальное, например `mlmcrm-backups-xxxx`; файлы **Private**; Object Lock выключен.
3. В созданном бакете **Lifecycle Settings → Use custom lifecycle rules** (три правила):
   - `daily/`: «Days Till Hide» 7, «Days Till Delete» 1;
   - `weekly/`: 28 и 1;
   - `monthly/`: 90 и 1.
4. **Application Keys → Add a New Application Key**: имя `github-backup`, доступ только к этому бакету, **Read and Write**. Сразу скопируйте **keyID** и **applicationKey** (второй показывается один раз).
5. На странице бакета запишите **Endpoint** вида `s3.us-west-004.backblazeb2.com`. Часть `us-west-004` это регион.

### 3. Пользователь только для чтения в Neon
Neon → ваш проект (с рабочей базой) → **SQL Editor**, выполните (придумайте длинный случайный пароль):

```sql
CREATE ROLE backup_reader WITH LOGIN PASSWORD 'ВАШ-ДЛИННЫЙ-СЛУЧАЙНЫЙ-ПАРОЛЬ';
GRANT pg_read_all_data TO backup_reader;
```

Адрес для копирования: возьмите `DATABASE_URL` из Vercel, замените в нём имя пользователя на `backup_reader` и пароль на новый, а в адресе хоста уберите `-pooler`, если он есть (копирование должно идти по прямому подключению). В конце должно стоять `?sslmode=require`.

### 4. Секреты в GitHub
GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Семь секретов:

| Имя | Что вписать |
|---|---|
| `BACKUP_DATABASE_URL` | адрес из шага 3 (пользователь `backup_reader`) |
| `BACKUP_AGE_RECIPIENT` | открытый ключ `age1...` из шага 1 |
| `BACKUP_S3_ENDPOINT` | `https://s3.us-west-004.backblazeb2.com` (ваш регион) |
| `BACKUP_S3_REGION` | `us-west-004` (ваш регион) |
| `BACKUP_S3_BUCKET` | имя бакета |
| `BACKUP_S3_KEY_ID` | keyID из шага 2 |
| `BACKUP_S3_KEY` | applicationKey из шага 2 |


### 5. Первый запуск
GitHub → **Actions → Backup → Run workflow** (выберите `main`). Через 2–3 минуты запуск должен быть зелёным, а в бакете B2 появится файл `daily/сегодняшняя-дата.dump.age`. Если красный: откройте запуск, красная аннотация вверху объяснит, что не так (например, «неверный адрес базы»); пришлите её мне.

### 6. Менеджер паролей: значения Vercel
Один раз сохраните туда значения из Vercel → Settings → Environment Variables (имя и значение каждой): `SECRETS_KEY` (особенно важно: без него не расшифровать сохранённые интеграции), `AUTH_SECRET`, `AUTH_URL`, `APP_URL`, `DATABASE_URL`, `SMTP_*`, `RESEND_API_KEY`, `MAIL_FROM`, `CRON_SECRET`, ключи Google и Telegram, если есть. Копии не хранят настройки сайта, только данные.

## Проверка раз в месяц (5 минут)
Заходите в хранилище и убеждаетесь, что в `daily/` свежие файлы, а размер примерно прежний. Красный запуск GitHub пришлёт письмом сам.

## Восстановление (учебная тревога и настоящая)
Копия восстанавливается в **новую пустую** базу Neon.

1. Neon → **Create project** (пустой): скопируйте его адрес подключения.
2. GitHub → Settings → Secrets → добавьте `RESTORE_DATABASE_URL` (адрес новой базы) и **временно** `BACKUP_PRIVATE_KEY` (закрытый ключ целиком из менеджера паролей, строка `AGE-SECRET-KEY-1...`).
3. **Actions → Restore → Run workflow**: в `object` впишите имя копии из хранилища (например `daily/2026-11-05.dump.age`), в `confirm` слово `RESTORE`.
4. Дождитесь зелёного запуска («Restored: N tables»).
5. **Сразу удалите секрет `BACKUP_PRIVATE_KEY`** из GitHub.
6. Если это настоящая авария: в Vercel замените `DATABASE_URL` на адрес новой базы, сделайте Redeploy, откройте сайт и проверьте вход и данные. Потеряется то, что было записано после ночной копии (не больше суток).
7. Если это учебная тревога: удалите пробный проект в Neon и секрет `RESTORE_DATABASE_URL`.

**Учебную тревогу проведите один раз сразу после настройки**, вместе со мной: так мы убедимся, что закрытый ключ из менеджера паролей действительно открывает копию.

## Чего в копии нет
- Настроек и ключей сайта (Vercel), записей DNS (Vercel), кода (GitHub: он сам хранит историю).
- Файлов из хранилища вложений: на рабочем сайте оно пока не подключено (`S3_*`). Когда подключим, добавим для него версионирование и копию.
- Тех, кого уже удалили из базы до ночной копии.
