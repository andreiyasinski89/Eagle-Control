# Перенос базы Neon во Франкфурт (ускорение сайта)

**Зачем.** Сайт на Vercel работает в Европе, а база сейчас может лежать далеко (например, в США). Каждый запрос к базе тогда идёт через океан, и страницы открываются медленнее. База во Франкфурте рядом с сайтом ускоряет всё.

**Что происходит.** Мы создаём новый проект Neon во Франкфурте, копируем в него все данные кнопкой на GitHub (старая база только читается, её не трогаем), проверяем, переключаем сайт на новую базу. Старая остаётся нетронутой как запасная, пока вы не убедитесь, что всё работает.

**Время:** около 30 минут. Лучше делать в тихое время (вечер/ночь): всё, что люди запишут между копированием и переключением, в новую базу не попадёт. Это несколько минут.

## Шаг 1. Новый проект в Neon
1. Neon → **New Project**.
2. **Region:** `Europe (Frankfurt)`. **Postgres version:** 17 или выше (как у текущего, если помните; иначе 17).
3. Имя: `mlmcrm-frankfurt`. Нажмите **Create**.
4. На странице проекта нажмите **Connect**. Вам нужны **две** строки подключения (переключатель **Connection pooling**):
   - **прямая** (переключатель выключен, хост без `-pooler`): для копирования;
   - **через пул** (переключатель включён, хост с `-pooler`): для сайта.
   Пароль в строках настоящий, никому в чат их не присылайте.

## Шаг 2. Адрес старой базы
В Vercel → Settings → Environment Variables → `DATABASE_URL` (нажмите на глаз и скопируйте значение). В хосте уберите `-pooler`, если он там есть: копирование должно идти по прямому подключению. В конце должно стоять `?sslmode=require`.

## Шаг 3. Два секрета в GitHub
GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Что вписать |
|---|---|
| `MIGRATE_SOURCE_URL` | адрес старой базы из шага 2 |
| `MIGRATE_TARGET_URL` | **прямая** строка новой базы из шага 1 (без `-pooler`) |

## Шаг 4. Копирование
GitHub → **Actions → Migrate database → Run workflow** → в поле впишите слово `MIGRATE` → **Run**.
Через 2–5 минут запуск должен стать зелёным. В журнале будет «done: N tables, and the row counts agree». Если красный, красная надпись вверху объяснит причину (например, «новая база не пустая»). Пришлите её мне. В журнале нет ни адресов, ни паролей, ни данных.

## Шаг 5. Переключение сайта
1. Vercel → Settings → Environment Variables → `DATABASE_URL` → **Edit**.
2. Вставьте строку **через пул** новой базы (хост с `-pooler`) и в конец допишите параметры, чтобы получилось примерно так:
   `postgresql://…-pooler….neon.tech/neondb?sslmode=require&pgbouncer=true&connection_limit=5`
   (если в строке уже есть `?sslmode=require`, добавьте остальное через `&`).
3. **Deployments → ⋯ → Redeploy** (последний Production).
4. Откройте `https://mlmcrm.app/api/health`: должно быть `{"status":"ok","db":"up"}`. Войдите в приложение и проверьте, что ваши данные на месте.

Что дают параметры: `pgbouncer=true` и `-pooler` говорят сайту ходить через пул соединений Neon, `connection_limit=5` не даёт сайту открыть слишком много соединений.

## Шаг 6. Уборка
1. **Сразу удалите оба секрета** `MIGRATE_SOURCE_URL` и `MIGRATE_TARGET_URL` из GitHub.
2. Старую базу оставьте на 1–2 недели как запасную, потом удалите проект в Neon.
3. Когда настроим ночные бэкапы, они должны смотреть на **новую** базу: роль `backup_reader` создаётся уже в ней.

## Если что-то пошло не так
Верните в Vercel старое значение `DATABASE_URL` и сделайте Redeploy: сайт снова работает на старой базе (она не менялась). Данные, записанные в новую базу за это время, придётся перенести отдельно, напишите мне.

## Про «усыпление» базы
Neon на бесплатном плане усыпляет базу через 5 минут без запросов, первое открытие после паузы медленнее (приложение это переживает: оно повторяет запрос). «Держать базу бодрой» постоянными запросами можно, но это тратит месячный лимит часов работы базы на бесплатном плане, поэтому по умолчанию не включено. Если у вас платный план Neon, скажите, и мы добавим регулярный пинг `/api/health`.
