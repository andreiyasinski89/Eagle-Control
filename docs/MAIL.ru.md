# Почта и вход: что делать, если люди не могут войти

Новые люди входят по ссылке из письма. Если письмо не уходит, не может войти никто, и каждый видит одно и то же: «Не удалось отправить ссылку».

## Что случилось 4 ноября 2026

В логах Vercel стояла ошибка `535 5.7.8 Username and Password not accepted (BadCredentials)`. Это Gmail отказал в пароле: пароль приложения, с которым сайт отправлял письма, перестал действовать (его отзывают, когда меняют пароль Google или настройки безопасности). Пока пароль не заменили, ни одно письмо не уходило.

## Как починить прямо сейчас (5 минут)

1. Откройте https://myaccount.google.com/apppasswords, войдя в тот же аккаунт Google, с которого идут письма. Двухэтапная проверка должна быть включена.
2. Удалите старый пароль приложения «MeetOwl», если он есть, и создайте новый (название MeetOwl). Скопируйте 16 букв.
3. В Vercel → проект → **Settings → Environment Variables** замените значение `SMTP_PASS` на новый пароль. Остальное должно быть так: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_USER=ваш адрес Gmail`, `MAIL_FROM="MeetOwl <ваш адрес Gmail>"`.
4. **Deployments** → у последней сборки три точки → **Redeploy**. Без этого новый пароль не подействует.
5. Откройте в MeetOwl `/admin/setup`, раздел «Почта для ссылок входа», нажмите «Проверить»: на ваш адрес придёт пробное письмо. Если оно не пришло, под кнопкой будет точная ошибка сервера.

## Как теперь видно, что почта сломалась

- Каждая неудачная отправка записывается (причина и слова самого сервера, без адресов, только домен) и пишется в логи Vercel строкой `[mail] not sent: ...`.
- В панели администратора (`/admin`) появляется красная полоса «не удалось отправить N писем за сутки» со ссылкой на проверку.
- Человек, которому не ушло письмо, видит честное сообщение: «у нас не работает отправка писем, это не ваша вина, попробуйте через 10–15 минут», а не «проверьте адрес».
- Сбои, которые проходят сами (сервер не ответил, просит подождать), повторяются два раза автоматически. Отказ в пароле не повторяется: он сам не пройдёт.

## Почему Gmail ненадёжен и что делать дальше

Gmail как почтовый сервер для сайта подводит по трём причинам: суточный лимит (около 500 писем, у новых ящиков меньше), блокировки при частых входах с серверов Vercel и отзыв пароля приложения при любой смене настроек безопасности.

Надёжный путь, когда появится свой домен (например, meetowl.ai):

1. Зарегистрируйтесь на resend.com (бесплатно 3000 писем в месяц).
2. Добавьте домен в Resend и внесите 2–3 записи DNS, которые он покажет.
3. В Vercel задайте `RESEND_API_KEY` и `MAIL_FROM="MeetOwl <noreply@ваш-домен>"`, сделайте Redeploy. Сайт сам начнёт отправлять через Resend (`RESEND_API_KEY` важнее SMTP).

Без своего домена Resend отправляет только на адрес владельца аккаунта, так что для регистрации чужих людей не подходит.

## Вход через Google: письмо не нужно вовсе

Одна кнопка «Войти через Google»: не нужно ждать письмо, ссылка не может сгореть, не нужна почта на нашей стороне. В коде она уже есть, нужны только ключи. Пошаговая инструкция с готовыми адресами для вставки: `/admin/setup` → «Вход через Google». Когда ключи (`AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`) заданы и сделан Redeploy, кнопка появится на странице входа сама.

Важно: на экране согласия Google нажмите **Publish app**, иначе войти смогут только добавленные вами тестовые пользователи.
