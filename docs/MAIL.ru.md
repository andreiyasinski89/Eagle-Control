# Почта и вход: что делать, если люди не могут войти

Новые люди входят по ссылке из письма. Если письмо не уходит, не может войти никто, и каждый видит одно и то же: «Не удалось отправить ссылку».

## Что случилось 4 ноября 2026

В логах Vercel стояла ошибка `535 5.7.8 Username and Password not accepted (BadCredentials)`. Это Gmail отказал в пароле: пароль приложения, с которым сайт отправлял письма, перестал действовать (его отзывают, когда меняют пароль Google или настройки безопасности). Пока пароль не заменили, ни одно письмо не уходило.

## Как починить прямо сейчас (5 минут)

1. Откройте https://myaccount.google.com/apppasswords, войдя в тот же аккаунт Google, с которого идут письма. Двухэтапная проверка должна быть включена.
2. Удалите старый пароль приложения «MLM CRM», если он есть, и создайте новый (название MLM CRM). Скопируйте 16 букв.
3. В Vercel → проект → **Settings → Environment Variables** замените значение `SMTP_PASS` на новый пароль. Остальное должно быть так: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_USER=ваш адрес Gmail`, `MAIL_FROM="MLM CRM <ваш адрес Gmail>"`.
4. **Deployments** → у последней сборки три точки → **Redeploy**. Без этого новый пароль не подействует.
5. Откройте в MLM CRM `/admin/setup`, раздел «Почта для ссылок входа», нажмите «Проверить»: на ваш адрес придёт пробное письмо. Если оно не пришло, под кнопкой будет точная ошибка сервера.

## Как теперь видно, что почта сломалась

- Каждая неудачная отправка записывается (причина и слова самого сервера, без адресов, только домен) и пишется в логи Vercel строкой `[mail] not sent: ...`.
- В панели администратора (`/admin`) появляется красная полоса «не удалось отправить N писем за сутки» со ссылкой на проверку.
- Человек, которому не ушло письмо, видит честное сообщение: «у нас не работает отправка писем, это не ваша вина, попробуйте через 10–15 минут», а не «проверьте адрес».
- Сбои, которые проходят сами (сервер не ответил, просит подождать), повторяются два раза автоматически. Отказ в пароле не повторяется: он сам не пройдёт.

## Resend с доменом mlmcrm.app (надёжная почта)

Сайт отправляет через Resend, если задан `RESEND_API_KEY`. Если Resend отказал (домен ещё не подтверждён, ключ неверен, сервис недоступен) **и рядом настроен ящик Gmail** (`SMTP_USER`, `SMTP_PASS`), письмо уходит через Gmail. Поэтому Gmail оставляйте настроенным, и добавление Resend не может отрезать людей от входа.

1. Зарегистрируйтесь на https://resend.com.
2. **Domains → Add Domain** → `mlmcrm.app` → Add. Resend покажет 3–4 записи DNS: обычно `MX` и `TXT` для имени `send`, `TXT` (длинный ключ DKIM) для имени `resend._domainkey`, по желанию `TXT` для `_dmarc`.
3. Добавьте каждую в Vercel: **Domains → mlmcrm.app → DNS Records → Add**. Поля Name, Type и Value копируйте из Resend как есть (для `MX` ещё Priority). Имя пишется без `.mlmcrm.app`.
4. В Resend нажмите **Verify**, пока домен не станет **Verified** (от минут до часа).
5. **API Keys → Create API Key**, право **Sending access**. Скопируйте ключ `re_...`.
6. В Vercel → Environment Variables (Production): `RESEND_API_KEY` = ключ, `MAIL_FROM` = `MLM CRM <noreply@mlmcrm.app>`. Redeploy.
7. В MLM CRM `/admin/setup` → «Почта для ссылок входа» → «Проверить»: «через Resend» значит всё хорошо; «дошло через Gmail, Resend отказал» значит ищите причину по приписанному ответу Resend.

## Вход через Google

Одна кнопка вместо письма. В Google Cloud (console.cloud.google.com/apis/credentials):
1. Создайте проект, **OAuth consent screen**: External, название «MLM CRM», ваша почта. Нажмите **Publish app**, чтобы входили все, а не только добавленные тестовые пользователи.
2. **Create credentials → OAuth client ID → Web application**.
3. **Authorised JavaScript origins:** `https://meetowl-app.vercel.app` (и `https://mlmcrm.app`, когда домен станет основным).
4. **Authorised redirect URIs:** `https://meetowl-app.vercel.app/api/auth/callback/google` (и `https://mlmcrm.app/api/auth/callback/google`).
5. В Vercel (Production): `AUTH_GOOGLE_ID` (кончается на `.apps.googleusercontent.com`), `AUTH_GOOGLE_SECRET`. Redeploy.
6. На странице входа появится «Войти через Google». Человек с тем же адресом почты, что уже есть в системе, входит в свой прежний кабинет (аккаунты связываются по адресу, Google его подтверждает).

## Почему Gmail ненадёжен и что делать дальше

Gmail как почтовый сервер для сайта подводит по трём причинам: суточный лимит (около 500 писем, у новых ящиков меньше), блокировки при частых входах с серверов Vercel и отзыв пароля приложения при любой смене настроек безопасности.

Надёжный путь, когда появится свой домен (например, meetowl.ai):

1. Зарегистрируйтесь на resend.com (бесплатно 3000 писем в месяц).
2. Добавьте домен в Resend и внесите 2–3 записи DNS, которые он покажет.
3. В Vercel задайте `RESEND_API_KEY` и `MAIL_FROM="MLM CRM <noreply@ваш-домен>"`, сделайте Redeploy. Сайт сам начнёт отправлять через Resend (`RESEND_API_KEY` важнее SMTP).

Без своего домена Resend отправляет только на адрес владельца аккаунта, так что для регистрации чужих людей не подходит.

## Вход через Google: письмо не нужно вовсе

Одна кнопка «Войти через Google»: не нужно ждать письмо, ссылка не может сгореть, не нужна почта на нашей стороне. В коде она уже есть, нужны только ключи. Пошаговая инструкция с готовыми адресами для вставки: `/admin/setup` → «Вход через Google». Когда ключи (`AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`) заданы и сделан Redeploy, кнопка появится на странице входа сама.

Важно: на экране согласия Google нажмите **Publish app**, иначе войти смогут только добавленные вами тестовые пользователи.
